US Passports Production Tracking System

US Department of State · Bureau of Consular Affairs

↗ demo ⎇ repo

Abstract: In 2022, the US Department of State struggled to maintain its passports production obligations as demand for US passports soared to unprecedented heights. Today, systems like Ethan's US Passports Production Tracking System enable the Department to maintain and exceed these obligations. By seamlessly integrating Microsoft's 365 Office suite (i.e., Excel, Power Automate) with bespoke, interactive scripts, Ethan's system informs passports management with both top-level and granular data-driven insights. Notably, while operating within internal network security constraints, Ethan's architecture contributed to significant (by up to 40%) production improvements in 2025, compared to fiscal year 2024.

Keywords:
Data Architecture Data Analytics Excel Microsoft 365 HTML CSS JavaScript
I. Outcomes
Ethan's US Passports Production Tracking System operates within Department security constraints to provide semi-live data snapshots of production progress, both at the individual employee level and office-wide. Developed in 2025, Ethan's system continues to provide the following capabilities:
  • Casework Sorting: Automatically sorts ingested casework by priority, ensuring that: (1) applicants with urgent travel receive their passports expiditiously, and (2) aging cases are appropriately addressed to maintain current turnaround obligations.
  • UX/UI: Provides a bespoke, user-friendly GUI with which both management and working-level employees interface.
  • Data Storage: Collects and stores casework data and employee actions in Microsoft Excel.
  • Data Analysis: Parses the collected data to both present operational statistics and generate documentary reports for both working-level employees and management.
  • Network Security: Accomplishes the above with security-compliant architecture, using only scripts and the Microsoft 365 Office Suite.

II. High-Level Requirements

The high-level requirements were defined by management and employees based on regional office needs. Previously, employees had been communicating their actions on high-priority casework through a Microsoft List. This legacy process was determined untenable, as a singular Microsoft List could provide neither management with high-level operational statuses nor employees with granular, organized case updates. III. Constraints

The system architecture and scope was constrained primarily by the Department's internal security requirements and the user base's data literacy. Locally hosted scripting was permissible, for instance, but traditional software development was not. This constraint therefore prevented local scripts from fetching external data. Furthermore, given that the user base's data literacy was not uniform, a user-friendly GUI was required.

IV. System Architecture

To accomodate the outlined constraints, Ethan's system integrated a bespoke frontend GUI with Power Automate driven automation, a custom JavaScript analysis engine, a live Excel repository, and a JavaScript intermediary. Specifically, Power Automate captured employee-reported actions, then added each action as a row to an Excel table. V. The HTML vs Power BI Debate

While effective at integrating seamlessly with Microsoft 365 systems, Power BI is significantly constrained by its drag-and-drop development interface and its frontend UI. During the system's development cycle, Ethan determined that presenting a legible, user-friendly interface took precedence over seamless integration, as the system's user base were not data analysts themselves.
